GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトで作業を調整できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- 作業中のセッションにライト モードの切り替えを追加するよう依頼します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ カスタムエージェントは、高コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けに、ライト モードも追加してほしいという依頼がありました。新しい会話を最初から始めず、既存のセッションに追加の指示を出します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが確認したファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの操作を確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、別の方法を試すようエージェントに促します。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントが高コントラスト モードを実装し終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライト モードを追加するようエージェントに依頼する

高コントラスト モードができたら、同じ会話を使ってライト モードの切り替えを追加します。既存のセッションを続けることで、エージェントは前の作業で変更したコンポーネント、スタイル、local storage のパターンを把握した状態で作業できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を確認し、ライト モードの追加を提案する様子を見ます。
3. 高コントラスト モードの場合と同様に、新しい編集を確認して、差分ごとに **Keep** または **Undo** を選びます。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好ましくない方法で切り替え UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を追加してプロンプトを送り直します。

> [!TIP]
> 進行中のセッションに追加の指示を出すと、最初からやり直すより短時間で調整できます。「カスケーディング スタイル シート (CSS) を簡潔にして重複するセレクターの代わりに CSS 変数を使う」などの修正、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む」などの方向修正、「両方の切り替えにキーボード ショートカットも追加する」などの範囲拡張を依頼できます。

## 作業中の変更を確認する

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティの実践 (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HyperText Markup Language (HTML)、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して指示を追加しました。ファイル編集ごとに確認し、変更を承認または取り消し、コンテキストを保ったまま追加のプロンプトで作業範囲を広げました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を承認または取り消す方法
- 追加のプロンプトで進行中のセッションに指示を出す方法
